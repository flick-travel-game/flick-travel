## ゲームの かたち
「表示された ひらがなを フリックで 打ち写す」タイピング。打ち終わると 説明(1〜3文)が 出る。説明の 下に 📘 分野(中分類) と 📝 分野の 札。

## 1語の 形(JSON)
{"id":"sc-isms","name":"ISMS","reading":"あいえすえむえす","journey":"sekyuriti","category":"管理のしくみ","difficulty":2,"type":"concept",
 "emoji":"📘","mapNode":"sekyuriti:isms","field":"セキュリティ","ruleset":"テクノロジ系","relatedTerms":["sc-kimitsusei"],
 "description":"情報セキュリティマネジメントシステムの 略です。会社が 情報を 守る ための 方針を 決め、PDCA で 見なおし つづける しくみの ことで、JIS Q 27001 で 決まっています。"}
- id: 旅の 頭文字2つ + "-" + 英小文字(keiei = ke / homu = ho / senryaku = se / shisutemu = ss / kaihatsu = ka / service = sv / kiso = ki / konpyuta = ko / nettowaku = nw / sekyuriti = sc)
- name: 画面に 出す 名前(シラバスの 書きかた。略語は 略語で よい: ISMS・SLA)。長すぎる ときは 短く
- reading: **ひらがなと ー だけ**。数字は ひらがな(5G → ふぁいぶじー / 2進数 → にしんすう)。ゆれは "acceptedReadings":["よみ1","よみ2"](先頭は reading)
- difficulty: 1 = 入門(学校や 会社で IT を 使う 人なら 知っておきたい。小学生も)/ 2 = 中級(ITパスポート試験の 基本)/ 3 = 上級(受かる 人の ことば: 略語の ちがい・計算・ひっかけ・新しい 用語)
- type: いつも "concept"
- category: 図鑑で しぼる 分類(短い 日本語。旅の 中で 4〜8種類)
- emoji: 1つ。⚠️ こわい 絵文字(💀🩸⚰️💣)・会社の ロゴに 見える もの(🍎🪟)を 使わない
- mapNode: その 旅の 図の 場所(下の 表から)
- field: シラバスの 中分類(上の 3。旅ごとに 使える ものが 決まっている)
- ruleset: 分野の 札(field で 決まる)
- relatedTerms: **同じ ファイルの 中の** id を 1〜3個
- formula(あれば): 計算の 式の 見本(40字以内。損益分岐点・稼働率・ROE など)
- description: 1〜3文・**130字以内**。やさしい です・ます。語と 語の あいだに 半角スペース(上の 例のように)。
  **ITパスポートの 目線**(会社で IT を 使う 人が 何を 知っておくか・どんな ときに 使うか)。略語は フルスペルか 日本語の 名前を 1回 入れる。
  ⭐ 上級は **ひっかけ**(SaaS / PaaS / IaaS・機密性 / 完全性 / 可用性・MTBF / MTTR・RFI / RFP・請負 / 準委任 / 派遣・著作権 / 特許権・ホワイトボックス / ブラックボックス・直列 / 並列 の 稼働率・共通鍵 / 公開鍵)に 気づける 1文を 入れる
