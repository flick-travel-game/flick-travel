# フリックITパスポート: ⭕❌ 一問一答の 作りかた

本物の ITパスポート試験は **4つから 1つ えらぶ 100問・120分**(CBT)。4つの 文の 正しい / まちがいを 見分けられれば 多くの 問題が 解ける。
この ゲームでは 1つの 文ずつ ⭕❌ で 練習し、🎯 模擬試験では ⭕❌ の 文を 同じ 分野(ストラテジ系 / マネジメント系 / テクノロジ系)から 4つ ならべて「正しい(誤っている)ものは どれか」の 4択に する。
合否を 分けるのは **略語の 意味の ちがい・計算・言葉の 入れかえ**(SaaS / PaaS / IaaS・機密性 / 完全性 / 可用性・MTBF / MTTR・請負 / 派遣・著作権 / 特許権・共通鍵 / 公開鍵)。**約1,200問**。

## 旅ごとの 問題数
keiei 120 / homu 120 / senryaku 120 / shisutemu 110 / kaihatsu 120 / service 110 / kiso 120 / konpyuta 120 / nettowaku 120 / sekyuriti 140(= 1,200)

## 決まり
1. `PROMPT.md` の「いちばん 大事な 決まり」を ぜんぶ 守る(中身は シラバス Ver.6.5 と facts-A/B/C.md の ものだけ・いまの 法律が 答え・攻撃の やりかたを 書かない・こわく しない・実在の 会社や 製品を 書かない)
2. **答えが 1つに 決まる 文**だけ。あいまいな 文・人に よって 答えが 分かれる 文は 作らない。主語(何の 話か)を はっきり 書く
3. **⭕ と ❌ は おおよそ 半分ずつ**(各旅 ⭕ 40〜60%)
4. **ひっかけを 多く**(上級は とくに): 略語の 入れかえ(SaaS ↔ PaaS ↔ IaaS / RFI ↔ RFP / MTBF ↔ MTTR / BCP ↔ BCM / CRM ↔ SCM ↔ ERP / CSIRT ↔ SOC)・性質の 入れかえ(機密性 ↔ 完全性 ↔ 可用性 / 共通鍵 ↔ 公開鍵 / ホワイトボックス ↔ ブラックボックス / 直列 ↔ 並列 / 主キー ↔ 外部キー / キュー ↔ スタック)・法律の 入れかえ(著作権 ↔ 特許権 / 請負 ↔ 準委任 ↔ 派遣 / 不正アクセス禁止法 ↔ 不正競争防止法)・増える ↔ 減る
   ❌ の 文は **本物らしく 少しだけ ちがう**(言葉を 1つ 入れかえる・数字を 1つ 変える・向きを 逆に する)
5. **とき方**(`why`): なぜ ⭕/❌ か 1〜2文・**90字 以内**。❌ なら 正しい 形を 書く。やさしい です・ます
6. **どこの 話か**(`law`): 法律の 問題は 「著作権法」「個人情報保護法」「不正アクセス禁止法」の ように 法律名(条が facts に ある ときだけ 条も)。法律で ない 問題は シラバスの 小分類の 名前(「シラバス 61 情報セキュリティ」の ように 番号 + 名前)
7. 問題文(`q`): **80字 以内**。試験と 同じ「〜である。」「〜する。」の 形で よい(漢字は ふつうに 使う。ふりがなは 付かない)
8. 同じ ことを 聞く 問題を 2つ 作らない(同じ 事実の ⭕版と ❌版も 作らない)
9. **過去問・問題集・テキストの 文を 写さない**。自分の ことばで(「よく 出る 考えかた」を 自分の 文に)
10. `dv`: 1 = 入門(各旅 10問ほど)/ 2 = 中級 / 3 = 上級(略語の ちがい・計算・ひっかけ)。上級を 半分 以上
11. `term`: その 問題に いちばん かかわる ことばの id(`terms-<旅>.json` に ある もの。無ければ 書かない)
12. `rs`: 分野の 札。keiei・homu・senryaku・shisutemu = ストラテジ系 / kaihatsu・service = マネジメント系 / kiso・konpyuta・nettowaku・sekyuriti = テクノロジ系
13. ⭐ 4択の 模擬試験で 同じ 分野の 文が 4つ ならぶので、**1つの 文だけで 意味が 分かる**ように(「この 方式は」の ような 前の 文に たよる 書きかたを しない)

## 形(JSON。`tools/itpass/maru-<旅>.json` に 配列で)
{"id":"sc-m001","q":"情報セキュリティの可用性とは、許可された人が必要なときに情報を使える状態にしておくことである。","a":true,
 "why":"可用性は「使いたい ときに 使える」こと。正しい ままを 守るのは 完全性、見せない のは 機密性です。","law":"シラバス 61 情報セキュリティ","dv":2,"term":"sc-kayosei","rs":"テクノロジ系"}
- id: 旅の 頭文字2つ + "-m" + 3けた(ke / ho / se / ss / ka / sv / ki / ko / nw / sc)
- a: true = ⭕ / false = ❌
- 確かめは `python3 tools/itpass/maru_check.py`
