## マネジメント系

| 事実 | 出どころ |
|---|---|

| ① の 用語例: 機能要件・非機能要件・共同レビュー・品質特性(機能性・効率性・使用性・信頼性 など) | シ p.27 / 25(1)① |

| ③ の 用語例: コーディング・**ホワイトボックステスト**・デバッグ・コードレビュー(単体テストは 個々の プログラムの 誤り(バグ)を 確かめる) | シ p.27 / 25(1)③ |

| 作成物は 3つ: プロダクトバックログ・スプリントバックログ・インクリメント(シラバスに あるのは 前の 2つ) | スクラムガイド 2020 / シ p.29 |
| 共通フレーム = ソフトウェア開発と その 取引の 適正化に 向けて 作業項目を 1つ1つ 定義し 標準化した もの として **SLCP(Software Life Cycle Process)** が ある | シ p.29 / 26(4)① |
| **CMMI**(Capability Maturity Model Integration: 能力成熟度モデル統合)= 開発組織の プロセス成熟度を モデル化。成熟度を **5段階**の レベルで 定義 | シ p.29 / 26(4)② |

### 内部統制・IT ガバナンス(中分類12)
| 事実 | 出どころ |
|---|---|
| 内部統制 = 健全かつ 効率的な 組織運営の ための 体制を 企業が **自ら 構築し 運用する** 仕組み。実現には **業務プロセスの 明確化・職務分掌・実施ルールの 設定・チェック体制の 確立**が 必要。用語例: **モニタリング**・**レピュテーションリスク** | シ p.33〜34 / 32(1) |

| ⚠️ 4つの 目的・6つの 基本的要素は **シラバスの 文には 無い**(シラバスの 用語例は モニタリング・レピュテーションリスク だけ) | シ p.33〜34 |

| **JIS Q 38500(IT ガバナンス)** は 中分類2 法務の「標準化団体と 規格」の 用語例(係 A/C と かぶる)。中身の 文言は 未確認 | シ p.13 / 8(3) |
